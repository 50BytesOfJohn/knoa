Search, from zero

Six ways to rebuild the top of Knoa's main screen around one idea: you find things by narrowing, one word at a time. Every window below is live. Type, press ↵ to lock a word in, ⌫ on an empty field to take the last one back, or press "Play" to watch "outfits ↵ brown ↵ jacket".

Research

What we learned

Knoa's own research report already holds the most important fact: people refind saved things mostly by recognising them, not by recalling exact words. They remember fragments: it was brown, it was a jacket, it was on some shop, I saved it a few weeks ago. Good search lets you pile up fragments until the thing appears.

Narrowing beats querying

mymind's "deep search" lets you add a word, press Enter, add another. Pinterest's guided search shows the next words to add as pills under the bar. Both turn search into a series of small, safe steps instead of one perfect query.

Only offer what exists

Raindrop lists a filter only when at least one bookmark matches it. Every suggestion and refinement in these concepts shows a count and disappears at zero, so you can never narrow into an empty page by accident.

Tokens, not syntax

Apple's guidelines treat a token as a selectable, editable term that filters the others. Typed syntax (#tag, site:, runtime>2h) stays as a shortcut for power users and is the text form of the same tokens.

Separate "what" from "how"

Linear keeps what a view shows (filters) apart from how it looks (a Display menu at the top right). The sliders button inside Knoa's pill mixes the two. It belongs with settings in the corner.

Where users get let down

Reviews of bookmark managers repeat a few complaints: search that only reads titles, results that are not ranked by relevance, wrong AI tags that pollute the filters, and syntax you have to memorise. Anecdotal, but consistent.

Keep the page calm

Apple's guidance is to make results better before adding scopes. mymind wins on calm. So: no permanent filter panel, no query builder on screen, one row at most under the bar, and it only appears when it has something to offer.

Scope

What the new top bar needs

Sorted so the alpha stays small. Everything in the first column works on top of the Query Knoa already has (text, kind, tags, sites, fields, place), so the first version needs no new search engine.

Now

  • Enter locks a word in as a tokenEach next word searches inside the last result.
  • Typed suggestions with countsTag, folder, kind, site. Picked with ↑↓ and ↵. Zero-count values never show.
  • Refinement rowKinds and tags that split the current results. Replaces the fixed kind chips.
  • ⌫ edits, click removesFirst ⌫ selects the last token, second removes it.
  • Place as a token"in Outfits" is the first token; remove it to search everything.
  • View options and settings move to the top-right corner

Next

  • Recent searches on empty focus
  • Save a search as a smart foldermymind's Smart Spaces; a place in the sidebar.
  • Exclude a word-word, or ⌥-click a refinement.
  • Typo tolerance and page text in the index
  • Zero results offers the token to drop

Later, with AI

  • Plain-language search that turns into tokens"brown jackets I saved last month". Always shown as editable tokens, never a black box.
  • Meaning-based matches"coat" finds "parka".
  • Colour and object search for images
  • Date tokens"last month", "this summer".

Not doing

  • A visible query builder with AND/OR
  • A permanent filter panel on the main screen
  • A separate search page or results mode
  • Any setting or view control inside the search field
A

Trail

The mymind idea, done fully. One floating pill; each ↵ turns what you typed into a token, and the row under it offers the next word to add, drawn from what is left.

How it behaves

  • Typing filters live; ↵ commits the highlighted suggestion, or the text itself.
  • Tokens sit inside the pill, joined by quiet chevrons, so it reads as a trail.
  • The refinement row replaces the kind chips: kinds first when the results are mixed, then tags.
  • "Save" turns the trail into a smart folder.

Good

  • Closest to how you described it.
  • Keeps the approved centred pill and the calm layout.
  • One row under the bar, only when useful.

Watch out

  • Long trails need to scroll inside the pill.
  • The refinement row moves as results change; it needs a short fade.
B

Path

The search is a path, like a folder breadcrumb: Everything / outfits / brown / jacket. Click any step to go back to it. The bar becomes a full-width toolbar across the content.

How it behaves

  • The place is the first step; typing adds the next one.
  • Clicking a step drops everything after it, like going back.
  • "Narrow" is a line of plain words under the bar, not pills.

Good

  • Folders and searches feel like one thing: places you drill into.
  • Big type makes where you are obvious.
  • Corner controls sit naturally at the end of the toolbar.

Watch out

  • Gives up the floating pill from the approved design.
  • A path implies order; filters do not really have one.
C

Spotlight

The bar shrinks to a quiet launcher. Typing opens a large panel over the library, with grouped suggestions and the top matches, like Raycast or Spotlight. Tokens stay in the launcher when it closes.

How it behaves

  • Any key or ⌘K opens the panel; Esc closes it and keeps the tokens.
  • Suggestions grouped: Tags, Folders, Kinds, Sites, then top bookmarks.
  • ↵ on a bookmark opens it straight away.

Good

  • The library gets the most room when you are not searching.
  • Merges search with the planned command palette.
  • Room for richer suggestions (previews, counts, recent).

Watch out

  • The panel covers the cards you are narrowing.
  • Search becomes a mode, which the main-screen design avoided.
D

Facets

For precision. Text stays in the field; filters are explicit pills ("Tag is brown") with quiet facet buttons to add more. Close to Linear, simplified for a personal library.

How it behaves

  • Kind, Tag, Folder and Site each open a list of values with counts.
  • Typed suggestions work too; ↵ adds the filter pill.
  • Free text becomes a "Contains" pill.

Good

  • Unambiguous: you always see exactly what is applied.
  • Scales to typed fields later ("Runtime > 2h", "Year is 1999").

Watch out

  • Two rows of controls even when idle; the busiest option here.
  • Feels like a work tool, not a personal library.
E

Ask

Describe it in your own words. Knoa reads the sentence and shows how it understood it, as tokens you can remove or add to. In this mock the reading is a simple local match; the real one would use the AI.

How it behaves

  • ↵ reads the whole sentence and turns it into tokens.
  • Tokens the AI chose carry the AI dot, like everywhere else in Knoa.
  • Words it could not place stay as text.

Good

  • Lowest effort for vague memories.
  • Fits Knoa's "visible, reversible automation" principle.

Watch out

  • Needs a network and an LLM call; the vision says search never waits on either.
  • Best as a layer over A, not its own bar.
F

Headline

No search box at all. The title of the page is the search: it says "Everything" until you type, then your words replace it in large type. Strike a word to remove it. The most "mymind" in feel.

How it behaves

  • Typing anywhere writes into the headline.
  • Committed words join with dots; click one to remove it.
  • The line under it gives the count and words to narrow by.

Good

  • The calmest screen; type becomes the interface.
  • Uses Knoa's serif, gives the app a strong character.

Watch out

  • New users may not see that they can search.
  • Tag versus word versus folder is harder to show in plain type.
Top-right corner

Where view options and settings go

Every concept above puts them in the top-right corner of the content, away from search. These are three ways to dress that corner. The sidebar footer keeps the account; app settings can live in either place, but only one.

⌕ outfits › brown

1 · Three quiet icons

Add link, view options, settings. Familiar, matches Finder and Photos. Used in the concepts. The add button can move here from the sidebar so all actions live in one corner.

⌕ outfits › brown
Display

2 · "Display" plus a menu

A labelled Display button (layout, sort, summaries) and one ⋯ menu for settings, workspace and help. Clear what each does; one more word on screen.

⌕ outfits › brown

3 · One menu, with AI status

A single button opens view options with Settings at the bottom (⌘,). The AI's dot sits beside it and shows organizing progress, moving it out of the sidebar footer.

Recommendation

Build A, borrow from B, C and E

  1. Trail (A) as the base. It is the idea you described, it keeps the approved floating pill, and it adds one row only when there is something to narrow by.
  2. From Path (B): clicking a token in the trail jumps back to that step, which makes going back as easy as narrowing.
  3. From Spotlight (C): the suggestion list groups Tags, Folders, Kinds and Sites with counts, and lists the top bookmarks last so ↵ can open one directly.
  4. From Ask (E), later: a plain sentence typed into the same pill becomes AI-marked tokens. No separate mode.
  5. Corner option 1 for now: view options and settings as icons at the top right; the sliders leave the pill.

Headline (F) is the bold alternative if you want Knoa to look unlike any other app. I would keep it on the table and test it against A once both are clickable in the app.
